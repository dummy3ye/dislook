Development
===========

This page covers the repository layout, the npm scripts, and how the code is
tested.

Layout
------

::

    src/
      dislook.ts    CLI entry: arguments, printing, API requests
      snowflake.ts  decode, calendar helpers, ID extraction
      format.ts     durations and relative times
      env.ts        .env parsing and token lookup
      discord.ts    badges, channel types, CDN URLs
    tests/          unit tests for the modules above
    docs/           this documentation
    dist/           bundled output, generated by the build

The pure logic lives in the small modules so it can be tested without touching
the network or the terminal. ``dislook.ts`` is the only module with side
effects: it reads arguments, writes to stdout, and calls the Discord API.

Scripts
-------

``npm test``
    Run the unit tests once with vitest.

``npm run test:watch``
    Re-run tests on every change.

``npm run check``
    Typecheck, lint, and check formatting.

``npm run typecheck``
    Run ``tsc --noEmit``.

``npm run lint``
    Run ESLint.

``npm run format``
    Format everything with Prettier.

``npm run build``
    Bundle ``src/`` into ``dist/dislook.js`` with tsup.

``npm run check`` is the same gate CI runs. Run it, plus ``npm test``, before
opening a pull request.

Testing
-------

Tests use vitest and live in ``tests/``, mirroring the module names:

- ``snowflake.test.ts`` covers decoding, the calendar helpers, and ID
  extraction.
- ``format.test.ts`` covers durations, relative times, and the short ID form.
- ``env.test.ts`` covers ``.env`` parsing and token lookup.
- ``discord.test.ts`` covers badge decoding, CDN URLs, and the default avatar
  index.

Tests never call the network. Online behaviour is exercised by the CLI smoke
tests in CI, which run against a known ID with ``--offline`` and ``--json``.

A snowflake can be built from its parts with the helper at the top of
``snowflake.test.ts``:

.. code-block:: ts

    function makeSnowflake(ms: number, worker: bigint, proc: bigint, increment: bigint): bigint {
      const ts = BigInt(ms) - DISCORD_EPOCH;
      return (ts << 22n) | (worker << 17n) | (proc << 12n) | increment;
    }

Adding a module
---------------

1. Keep it pure: no I/O, no ``console``, no ``process``.
2. Export small functions with explicit types.
3. Add a matching ``tests/<module>.test.ts``.
4. Wire it into ``dislook.ts`` only where output is produced.

Formatting
----------

Prettier owns the style. Do not hand-format; run ``npm run format``. ESLint is
configured with ``eslint-config-prettier`` so the two do not fight over
whitespace.

Releasing
---------

``npm run build`` produces ``dist/dislook.js``. The package publishes only
``dist``, ``README.md``, and ``LICENSE``, so anything needed at runtime must be
bundled or listed in ``package.json``.
